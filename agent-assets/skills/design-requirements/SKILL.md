# Design requirements

1. Read the request and any previous artifact or review.
2. Inspect the project read-only when repository facts affect the requirements.
3. Restate the problem without changing the user's intended outcome.
4. Define goals and explicit non-goals.
5. Record assumptions separately from confirmed constraints.
6. Create stable requirement IDs in `REQ-NNN` form.
7. Give every requirement observable acceptance criteria.
8. Identify risks and questions whose answers could materially change the design.
9. When revising, resolve every required review finding and keep unaffected IDs stable.
10. Return only data matching the supplied JSON Schema.
